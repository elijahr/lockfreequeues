# 3.3.11-B Final Shape — v5.0.0 canonical surface reference

This doc captures the v5.0.0 surface that lands after the Phase 3.3.11-B
restructure (sub-dispatches B.1 → B.2 → B.2.5 → B.3). Doc C
(`design-queue-collapse-v5.0.0.md`) and the reframe rationale doc
describe the **earlier** v5.0.0 design that landed a single 10-param
unified `Queue` plus a standalone `UnboundedSipsic`. Those docs are
retained as historical context; the canonical surface for v5.0.0 is
what is documented here.

The Middle-axis typestate attachment (Lifecycle on the queue value;
Claim-state on the `ccMulti` producer/consumer view) is designed and
reserved in the 3.3.11-B brief but DEFERRED to follow-up sub-dispatch
B.4. The structural restructure documented below is complete and
green across orc/arc/refc/atomicArc+TSan/ASan; the typestate layer is
the only outstanding piece for the v5.0.0 tag.

## Type surface

Two top-level user-visible types, each with 6 generic params:

```nim
type
  BQueue*[T; ccProd, ccCons: static PinScopeCardinality; N, P, C: static int] = object
    ## Bounded lock-free queue. No debra integration. No `ST`/`RK`/
    ## `S`/`MaxThreads` axes. Cardinality dispatched via
    ## `when (ccProd, ccCons) is` inside the procs.

  Queue*[T; ccProd, ccCons: static PinScopeCardinality;
         ST: static DeallocationStrategy;
         S, MaxThreads: static int] = object
    ## Unbounded lock-free queue. Carries debra integration for all
    ## cardinalities EXCEPT `(ccSingle, ccSingle)`, which is absorbed
    ## from the standalone `UnboundedSipsic` (no debra, simple
    ## committed-flag protocol). The user-visible API is uniform.
```

The standalone `UnboundedSipsic[S, T]` type and its module
(`unbounded_sipsic.nim`) are **deleted** in 3.3.11-B.2.5 (Bundle G
completion). The body is absorbed into the `(ccSingle, ccSingle)`
branch of `Queue` verbatim — same field layout, same head/tail/storage
semantics, same committed-flag protocol.

## Smart constructors

Two generic ctors are the **primary surface** for new code:

```nim
proc newBQueue*[T; ccProd, ccCons: static PinScopeCardinality;
                N, P, C: static int]
  (): BQueue[T, ccProd, ccCons, N, P, C]

proc newQueue*[T; ccProd, ccCons: static PinScopeCardinality;
               ST: static DeallocationStrategy;
               S, MaxThreads: static int]
  (): Queue[T, ccProd, ccCons, ST, S, MaxThreads]
```

Plus the manager-borrowed `newQueue` overload that takes
`manager: ptr DebraManager[MaxThreads, debra.ccMulti|ccSingle]` for
non-sipsic unbounded cardinalities. The `(ccSingle, ccSingle)` Queue
absorbed-sipsic branch never consumes a manager.

Family-named **thin wrappers** are retained for grep continuity and
to minimize churn in tests + benchmark adapters + downstream call
sites:

- Bounded (BQueue-backed):
  `newSipsicQueue`, `newMupsicQueue`, `newSipmucQueue`, `newMupmucQueue`.
- Unbounded (Queue-backed):
  `newUnboundedSipsicQueue`, `newUnboundedMupsicQueue`,
  `newUnboundedSipmucQueue`, `newUnboundedMupmucQueue`.

For new code, prefer `newBQueue` / `newQueue` directly. The wrappers
are pure ergonomic aliases — same underlying type, same `=destroy`
semantics, zero additional cost. (M4 alias-return lock: every wrapper
returns the user-visible `BQueue`/`Queue` alias, never a backing
type. M7 lock: the worked examples in CHANGELOG v5.0.0 position the
two-ctor surface as canonical primary; family wrappers as convenience
aliases.)

## Cardinality `{.error.}` gates

Six runtime `InvalidCallDefect` cardinality traps in the legacy unified
Queue are lifted to compile-time `{.error.}` overloads (3.3.11-B.2
Bundle E):

- Direct push on a `ccProd == ccMulti` BQueue.
- Direct pop on a `ccCons == ccMulti` BQueue.
- Direct batch push on a `ccProd == ccMulti` BQueue.
- Direct batch pop on a `ccCons == ccMulti` BQueue.
- Direct pop on a `ccCons == ccMulti` Queue.
- Direct batch pop on a `ccCons == ccMulti` Queue.

Plus two ctor-time `{.error.}` gates on the unbounded `(ccSingle,
ccSingle)` Queue manager-borrow overloads (the absorbed-sipsic branch
never takes a manager).

Each `{.error.}` string references the user-visible alias name only
(`BQueue`, `Queue`, `BQueueProducer`, `QueueProducer`, …) and never
leaks the backing `*Multi`/`*Single` type name — M5 R9 grep gate
enforces this.

## Middle-axis typestates (deferred to 3.3.11-B.4)

The 3.3.11-B brief reserves two typestates that attach to the
user-visible types via typestates 0.9.3's attachment-pragma surface:

1. **Lifecycle** on `BQueue[...]` and `Queue[...]` values:
   - States: `QueueInit`, `QueueDestroyed`.
   - Constructor emits init-transition; `=destroy` emits a
     `destructorTransition` from `QueueInit` to `QueueDestroyed`.
   - Every push/pop/getProducer/getConsumer requires `QueueInit`.

2. **Claim-state** on `BQueueProducer`/`BQueueConsumer`/
   `QueueProducer`/`QueueConsumer` views, **only on the `ccMulti`
   arm** of the two-type alias dispatch:
   - States: `Unclaimed`, `ProducerClaimed`, `ConsumerClaimed`,
     `BothClaimed`.
   - `getProducer()`/`attach()`/`detach()` drive the transitions.

Both typestate declarations live in the same module as their
consuming procs (F.3.5 intra-module containment, enforced by
typestates 0.9.3's cross-module prohibition at `pragmas.nim:633-642`).

Bundle F's implementation is deferred to 3.3.11-B.4 (a follow-up
sub-dispatch). The structural restructure (Bundles A/B/C/D/E/G) is
complete; Bundle F is the only remaining piece before the v5.0.0 tag.

## Bench-binary topology

Nine NIM_BINARIES (unchanged from HEAD `2ddca6a` at 3.3.11-B dispatch
start; the proactive `bench_spsc` / `bench_mpsc` split contemplated in
brief Bundle H2 is moot because those binaries are already
bounded-only — the bounded/unbounded iCache co-compilation topology
the H2 split was designed to prevent does not occur at HEAD):

```
bench_spsc                — Sipsic at 1p1c (BQueue, bounded only)
bench_mpsc                — Mupsic at {1,2,4}p1c (BQueue, bounded only)
bench_mpmc_mupmuc         — Mupmuc grid (BQueue, bounded only)
bench_mpmc_sipmuc         — Sipmuc shapes (BQueue, bounded only)
bench_unbounded_sipsic    — UnboundedSipsic at 1p1c
                            (Queue, absorbed-sipsic branch)
bench_unbounded_sipmuc    — UnboundedSipmuc at 1p{1,2,4}c (Queue)
bench_unbounded_mupsic    — UnboundedMupsic at {1,2,4}p1c (Queue)
bench_unbounded_mupmuc    — UnboundedMupmuc full grid (Queue)
bench_latency             — Latency suite (mixed)
```

All 9 binaries compile clean post-restructure. The `bench_unbounded_*`
adapters reach the absorbed `(ccSingle, ccSingle)` Queue branch
through `newUnboundedSipsicQueue` rather than the deleted
`newUnboundedSipsic`.
